# FlamingPiston — Site Architecture

*Inventory of the repository as of 26 Nov 2026 (approved homepage build + Phase 2A shared foundation, branch `redesign/premium-editorial`). Existing URLs are permanent: do not rename or move them. Future URL ideas are listed separately and are not routes yet.*

## 1. Stack and deployment

- Static HTML + CSS + vanilla JS. No framework, no CMS, no database, no backend.
- Source: GitHub `gaganmishra12/flamingpiston`, branch `main` → Hostinger hPanel Git auto-deploy to `public_html`.
- Local publishing scripts (Node + Python/Pillow): see §6.
- Apache `.htaccess`: www → non-www 301; old flat review URLs → folder URLs; `/index.html` → `/`; three consolidated duplicates; `/site/*` → root; custom `ErrorDocument 404 /404.html`.
- **Internal files are not served (Phase 2A):** `templates/`, `scripts/`, `docs/`, `data/`, every `*.md` (including `CLAUDE.md`, `README.md`, notes), `*.py`, `*.sh`, `*.log` and dot-files (`.git/`) return the normal 404 page via `RedirectMatch 404`. Hostinger's Git deploy copies the whole repository, so the server rules are the protection; `robots.txt` is not relied on. Tested on Apache 2.4 (mod_alias): blocked paths 404 with the custom page; public pages, assets, `search-index.json`, `sitemap.xml`, `feed.xml`, `robots.txt` and the existing 301s unchanged.
- `robots.txt`: allow all, disallow `/templates/` and `/scripts/`, sitemap link.
- Analytics: GA4 `G-QE7WZ5DCC6` via `/js/analytics.js` with Consent Mode v2 and a cookie banner (Accept / Decline).
- **State on 26 Nov 2026:** GitHub `main` is at 1b18b93 and still serves the 20 Nov redesign. The approved homepage (Phase 1), the documentation and the Phase 2A shared foundation exist only in the local branch / delivered zips and are **not yet committed or live**.

## 6. Publishing pipeline

Run from the repository root after adding or editing articles:

```
python3 scripts/make-thumbs.py         # optional: 800px WebP card thumbnails → images/thumbs/
python3 scripts/make-home-images.py    # only if data/homepage.json or data/cars.json crops changed
node scripts/reindex.js                # sitemap.xml, sitemap.html, feed.xml, search-index.json
node scripts/build-lists.js            # homepage sections, listing cards, filters, author list
node scripts/apply-shell.js            # head block, header, footer, search overlay on every page
```

All three Node scripts are idempotent: a second run changes nothing (since 27 Nov 2026 `reindex.js` dates the feed and listing `lastmod` values from the newest article, not the clock). Shared editorial rules (registry, live / draft / scheduled) live in `scripts/editorial.js`; `scripts/test-publishing.py` checks them on a temporary copy. `apply-shell.js` writes the **same masthead and footer into every page**, picks each page's active nav item from its editorial type, adds `fp-home.css`/`fp-home.js` only on the homepage, and leaves `<main>`, titles, meta, canonicals, Open Graph, JSON-LD and analytics untouched. `build-lists.js` writes only between `<!-- NAME:START -->` / `<!-- NAME:END -->` markers. Homepage markers (since 27 Nov 2026): HERO, STORIES, CARS-DATA, FEATURED, COMPARE, UPCOMING, REVIEW, GUIDES, CULTURE (NEWS was replaced by STORIES).

## 7. Known structural inconsistencies (preserve URLs; fix presentation only)

1. Guides and comparisons live in three folders: `/guides/`, `/comparisons/` **and** `/reviews/` (8 Brezza guides and 6 comparisons sit under `/reviews/`). Types are decided by the article tag, not the folder.
2. News stays flat at the root (`/news-*.html`); everything else uses folder URLs.
3. Car Culture is a curated mix of news and comparison URLs, not its own content type.
4. ~~Two header/footer systems coexist~~ — resolved in Phase 2A: one masthead and one footer on every page. Content layouts still differ (see `DESIGN-SYSTEM.md` §18).

## 8. Future URL principles

- New content types get folder URLs under a clear parent (`/cars/…`, `/compare/…`, `/tools/…`).
- Never move an existing article to match a new scheme; if consolidation is ever needed, use 301s in `.htaccess` and keep canonicals consistent.
- Model pages link to every article about that model, and articles link back (topic clusters).
- Interactive comparison results must use a distinct prefix from editorial comparisons to avoid duplicate content.
